# 設計メモ

## 配信キューをDBに置く

プロセスメモリだけのキューは再起動で未配信メッセージを失うため、PostgreSQLの状態を正本にしています。ワーカーはロックを取得してから処理し、処理中断後に再取得できる状態を残します。

## 冪等性キーを受付時に確定する

同じイベントを複数回受け付けても配信が増えないよう、Idempotency-Keyと送信元スコープを受付時に一意化します。再送は新しい受付ではなく既存配信の操作として扱います。

## 署名対象は生本文

JSONを再シリアライズしてから署名すると空白やキー順で検証結果が変わるため、受信した生本文にHMACを適用します。タイムアウト・再試行・デッドレターは別状態として記録します。
